## 2. カテゴリ「日常 (daily)」の内訳

X で実際にエンゲージするのは「質問」より「あるある」「共感」「観察」。10 本の内訳を以下に固定する:

| サブ角度 | 本数 | ねらい | 例 (≠ コピペ) |
|---|---|---|---|
| **愚痴・共感** | 3 | 子育てあるあるで「うちも〜」を引き出す | 「リビング、積木で毎晩つまずく問題。今日3回踏んだ」 |
| **面白エピソード** | 2-3 | 子どものかわいい/想像力ぶっ飛び瞬間 | 「3歳がブロックで『これお寿司ね』って渡してきた、なんでわかったん…」 |
| **悩み (本音)** | 2 | 保護者の本気の迷い。answer は求めない、共感の場 | 「来月の誕生日、まだ床にブロック散乱中なのに何足したらいいんだろう」 |
| **トレンド観察** | 1-2 | 最近の風向き観察。「○○増えてない？」系 | 「最近、木のおもちゃ再ブーム来てない？保育園の連絡帳でもよく見るし」 |
| **軽い質問** | 1 | 答えやすい一行 (重い質問は NG) | 「おもちゃ収納、見せる派？隠す派？」 |

合計 10 本。**重い質問 (「どうしたらいい？」教えて系) はゼロ**。重質問は X 文化で reach が伸びない。

## 3. 文字数・format ルール

### 文字数 (X は CJK weighted 280 上限)

意図的に**長短ミックス**する。下記の分布で 10 本を散らす:

- **短文 (60-100 weighted)** = 3-4 本: ぽろっとつぶやくテンポ
- **中文 (100-180 weighted)** = 4-5 本: 観察 + 一言オチ
- **長文 (180-260 weighted)** = 2-3 本: 軽いストーリー or 観察 + 共感

> CJK は 1 文字 = weight 2。半角英数・記号は weight 1。260 weighted ≒ 日本語 130 字。

### 絶対ルール (違反 = 該当 draft を破棄)

- **URL を 1 文字も含めない** (http も navi.omcha.jp も商品リンクも)
- **ハッシュタグ ( # ) を 1 個も含めない** (2026 の X は ハッシュタグで reach 下がる)
- **絵文字 ≤ 2 個 / 投稿** (中年っぽくならない。0 個でも OK)
- **名乗り (「いろママです」) 禁止**。一人称で書く
- **末尾シグネ「— ママより」「— 〇〇より」一切禁止** (アカウント本人=いろママが書いてる前提で署名は不要・不自然)
- **商品名・ブランド名は generic に**:「ブロック」「積木」「木のおもちゃ」「絵本」OK。「LEGO Duplo」「クーゲルバーン」など固有名詞は商品宣伝臭が出るので避ける
- **マウント口調禁止**:「みなさんは知らないかもしれませんが」「実は」など上から目線 NG
- **「教えて〜」「DM ください」NG**。エンゲージは自然な共感で取る
- **特定の家庭事情を勝手に決めつけない**: 「ワーママは大変」「専業の方は時間あるから」など NG

## 4. 良い例 (vibe を真似する)

```
1. (愚痴・短文) リビングの積木、毎晩裸足で踏むのもう日課。今日 3 回踏んだ。
2. (エピソード・中文) 黄色いブロックを「これカレー」って差し出してきた。
   ごはん食べた直後。色から連想なの…?
3. (共感・中文) 「自分の」を覚えた瞬間、ちょっと前まで紙くずでも遊んでたのに、
   どこで人は所有欲を獲得するんだろう
4. (悩み・長文) 来月の誕生日、もう床にブロックもパズルも散らばってて、何を足したら
   いいかほんとに分からない。「飽きないやつ」がほしいけど、子の飽きって読めなさすぎる
5. (トレンド観察・中文) 最近、木のおもちゃ再ブーム来てない? 公園のママ友も保育園の
   連絡帳も、なんか木製率が上がってる気がする
6. (ロボ cameo・中文) おもちゃロボに「色より形が先らしいよ」って教わったけど、うちは
   ずっと黄色いやつしか取らない。例外多すぎ問題
7. (軽い質問・短文) おもちゃ収納、見せる派? 隠す派? うちはついに見せ派に屈した
8. (エピソード・短文) ブロックで「東京タワー」って渡されたけど、限りなく富士山だった
9. (悩み・中文) ブロック増えすぎ問題、よその家でも起きてるんだろうか…買い足すたびに
   減らせず、いつのまにか箱が 4 つになってる
10. (愚痴・長文) 寝かしつけ後の片付け、ブロック踏まないように爪先で歩いてて、気づいたら
    つま先パンパン。これ立派な有酸素運動では? 育児ってフィットネスだ
```

> [!NOTE]
> 上記 10 本は **年齢を一切本文に出していない**。これがデフォルト推奨形式。
> 「3 歳の息子」のような年齢明記は内訳 10 本中 ≤ 2 本まで。年齢書く場合は **3 歳 / 男の子** で固定 (それ以外の数字・性別 NG)。

## 5. 出力フォーマット (厳守)

`data/engagement_queue_x.jsonl` の末尾に **10 行 append** する。既存行は触らない。
各行は 1 つの draft オブジェクト (改行なしの単一 JSON)。スキーマ:

```json
{
  "id": "eng-x-YYYY-MM-DD-NNN",
  "channel": "x",
  "persona": "iromama",
  "category": "daily",
  "subcategory": "vent|anecdote|worry|trend|light_question",
  "text": "...投稿本文 (URL/#禁止)...",
  "weighted_chars": 142,
  "generator": "jules_v1",
  "created_at": "YYYY-MM-DDTHH:MM:SS+09:00",
  "earliest_publish_at": null,
  "published_at": null,
  "post_id": null
}
```

- `id`: 本日の日付 + 連番 (001-010)。既存 jsonl の最終行を読んで連番続きにする
- `subcategory`: 上記内訳の sub-angle に対応
- `weighted_chars`: X 280 ルール (CJK=2, ASCII=1) で実測した整数
- `created_at`: 本日 (Asia/Tokyo) の現在時刻
- `earliest_publish_at`: 季節依存ネタ (例: 「もうすぐ七夕」) のみ未来日付 ISO、それ以外は `null`
- `published_at` / `post_id`: 必ず `null` (publish 後に notify_engagement.py が更新)

## 6. 重複・既存読み込み (重要 — Jules はここで手を抜きがち)

開始前に以下を **明示的に** 実行する:

1. `data/engagement_queue_x.jsonl` の **全行を読み**、`text` 一覧を作業メモに書き出す
2. その中から **モチーフ・キーワード** を抽出する。例:
   - 物体: 積木 / ブロック / パズル / お絵かき帳 / マグネット / 絵本 / 木のおもちゃ
   - 動作: 踏む / 並べる / 渡してくる / 「お店屋さん」 / 「東京タワー」
   - シチュエーション: 寝かしつけ / お風呂前 / 児童館 / 公園 / 収納整理
3. 新しい 10 本は **抽出したモチーフ・シチュエーションのリピートを最小化** する
   - 「ブロック踏む」「お店屋さん」「東京タワー」など特定の鉄板ネタは **既存 queue に 1 度でも出てたら今回使わない**
   - 同じ subcategory でも、扱う対象物 (積木 / 絵本 / お絵かき) を散らす
   - 全体で同じ動詞を多用しない (踏む / 散らかる / 飽きる など、過去 30 日で 2 回以上出てる動詞は今回控える)
4. ID 連番は最後行 +1 (date 変わったら 001 リセット)

**判定基準**: 既存 draft と新 draft の text を読み比べて「これ既存にあるやつだ」と人が思いそうなら破棄。バリエーション最優先。

## 7. 失敗ガード

- 10 本全て出せなかった場合は **0 本でも append しない**。空 PR でよい (空コミット禁止、close)
- `weighted_chars > 280` のものは内部で必ず短縮 or 破棄
- 既存行を 1 文字も変更しない (上書き禁止)
