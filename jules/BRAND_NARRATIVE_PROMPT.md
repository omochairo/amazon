# Jules プロンプト: ブランドハブ narrative 生成

このプロンプトは `.github/workflows/14-brand-narrative.yml` (#731 epic) から渡される。

## 目的とユーザー価値

`/brands/<brand>/` を訪れた読者 (主に 20〜40 代の保護者) が、30 秒以内に以下を判断できる
ようにする:

1. このブランドはどんな種類の知育玩具を作っているか (top_3_series から)
2. うちの子の年齢に合うか (avg_age_min_months から)
3. 価格帯はいくらから始まるか (lowest_price から)
4. ランダムな海外無名ブランドではなく、本サイトが独自評価で「上位」と判定したブランドか (tier から)

narrative はこの 4 点を読者に渡すための要約。SEO 目的の埋め草ではない。

## 出力先 (厳格)

- 新規作成のみ: `hugo/content/brands/{{BRAND}}/_index.md`
- 既存ファイルが存在する場合は即座に session 終了 (上書き禁止)
- 他のファイルへの追加・編集・削除は一切禁止 (scripts/, data/, hugo/layouts/, .github/ 全部不可)
- 一時ファイル (fix_*.py, tmp_*.json 等) を作業中に作っても、最終コミット前に必ず削除

## frontmatter (必須)

```yaml
---
title: "{{BRAND}}"
auto_generated: true
last_generated_at: "{{TODAY_ISO}}"
---
```

- `title:` は `{{BRAND}}` のまま (Hugo の term name fallback が空文字に落ちる trap 回避)
- `auto_generated: true` は将来の手書き保護フラグ (手書きは false にする)
- `last_generated_at` は ISO 8601 (+09:00)

## 本文構成 (3〜4 段落、合計 350〜500 字)

各段落の長さ目安と内容:

### 段落 1: ブランド紹介 (80〜130 字)

- `## {{BRAND}}はなぜ「{{キャッチコピー}}」なのか` を h2 見出しにする
- キャッチコピー例 (top_3_series の構成で判断):
  - モンテッソーリ系が多い → 「モンテッソーリ系の手頃な選択肢」
  - 木製系が多い → 「木のぬくもり系知育の入門」
  - プログラミング/STEM 系 → 「STEM 系知育の本命候補」
  - 海外ブランドで多シリーズ → 「海外定番ブランド」
  - 国内老舗 → 「日本の定番」
- 本文は **top_3_series を必ず 2 つ以上、太字** で書く (例: **アピター**、**Robot Bear**)
- count (商品数), tier の事実は本文中で自然に触れる (例: 「本サイトでも {{count}} 点を扱う」)

### 段落 2: 何が伸ばせるか (100〜150 字)

- top_3_series から推測される発達領域に絞る
  - ブロック / 組み立て系 → 空間認識・巧緻性・創造力
  - パズル系 → 論理思考・忍耐力
  - ごっこ遊び系 → 言語表現・社会性
  - 楽器系 → リズム感・聴覚識別
  - 乗り物系 → 分類力・知識欲
- avg_age_min_months から「{{X}} 歳ごろから」と書く (months / 12 切り捨て)
- 「〜と言われている」「〜される」など、ふんわり主張を避ける。
  断言できるのは top_3_series リテラルと avg_age_min_months のみ

### 段落 3: 価格帯と選びやすさ (60〜100 字)

- `lowest_price` を「最安 約 ¥{{N}} から」と具体的に出す
- tier の意味:
  - tier A → 「本サイトの独自知育スコアでも上位常連」
  - tier B → 「コスト対比で堅実なポジション」
  - tier C / D → 「価格対比でコストパフォーマンスが光るゾーン」

### 段落 4: 本サイト CTA (固定文・80 字程度)

```
本サイトでは、編集部独自の知育スコア (教育性 / 長寿命性 / 安全性 / コストパフォーマンスの 4 軸) で
{{BRAND}}商品を横断比較。お子さまの年齢にぴったりの 1 点を Amazon・楽天・Yahoo! の最安値で
見つけられます。
```

## 絶対に書いてはいけないもの (hallucination 防止)

以下は **データソースに無い限り** 書いてはいけない:

- 創業年・創業者・本社所在地・国
- 売上高・販売実績・〇〇万個突破などの数値
- 〇〇賞受賞・〇〇認証取得などの実績
- 「世界中で愛される」「人気 No.1」などの根拠不明な誇張
- 製品個別の機能詳細 (top_3_series に出ていない製品名/型番)

判断に迷ったら **書かない**。読者は事実が薄くても誠実な記事を信頼する。

(レゴ・タカラトミーは編集部が手書きで創業背景まで踏み込んでいるが、それは編集部が裏取りした上で書いている。Jules には裏取り能力がないので、与えられたデータの範囲だけで書く)

## 渡される変数 (workflow が `${{...}}` で注入)

- `{{BRAND}}`: ブランド名 (例: `Apitor`)
- `{{COUNT}}`: 商品数 (例: `4`)
- `{{TIER}}`: A/B/C/D
- `{{AVG_IVS_100}}`: 知育スコア平均 (例: `80.5`)
- `{{AVG_AGE_MIN_MONTHS}}`: 対象年齢の月齢中央値 (例: `63.0`)
- `{{LOWEST_PRICE}}`: 最安値 円 (例: `5999`)
- `{{TOP_3_SERIES}}`: カンマ区切り 3 シリーズ (例: `アピター, プログラミングおもちゃ, Robot Bear`)
- `{{TODAY_ISO}}`: 本日 ISO (例: `2026-05-30T10:00:00+09:00`)

## 失敗時の振る舞い

- top_3_series が 3 件未満、または全てブランド名そのもの (= 実質シリーズ情報なし) の場合、
  記事生成を中止して session を `FAILED` で終了する。中身の薄い narrative は害になるため。
- 同様に `count < 3` の brand は workflow 側で除外済みのはずだが、念のため Jules も
  自衛として count を確認する。
