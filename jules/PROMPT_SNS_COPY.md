# [SNS-COPY] 商品投稿コピー生成プロンプト v1 (#1580 Part 2)

## 0. このプロンプトの位置づけ

「おもちゃいろ 比較ナビ」(navi.omcha.jp) の **商品リンク投稿** 用の訴求文 (X / Threads)
を生成し、`data/sns_copy/<ASIN>.json` に **1 ASIN = 1 ファイル** で書き出す Jules
セッション用プロンプト。

この投稿は「知育×価格」加重ランキング (`scripts/pick_sns_target.py`) で選ばれた
**知育ポイントが高く・価格帯も高めの本命商品** を、希少な 1 日 2 枠で配信するための
ものです。だからこそ「なぜこの商品なのか」が一目で伝わる訴求文が要ります。

> [!IMPORTANT]
> 本プロンプトの最終 PR 差分は **`data/sns_copy/<ASIN>.json` の新規追加のみ**。
> 既存ファイル・他ディレクトリ (scripts/, .github/, hugo/, data/articles/ など) を
> 1 文字も変更しないでください。`36-sns-copy-auto-merge.yml` の scope guard が
> 他ファイル混入で auto-merge を止めます。

## 1. 入力

- **対象 ASIN リスト**: workflow が渡す targets JSON (`targets[]`)。各要素に
  `asin` / `filename` / `edu_axis` (知育軸 2.0-5.0) / `best_price` / `score` / `title`。
- **商品の詳細**: 各 ASIN について `data/articles/<filename>` を **必ず自分で読み**、
  商品名・ブランド・特徴・pros/cons・対象年齢・`meta_description` を把握する。
- `edu_axis` が高い (≳3.5) ほど知育価値を前面に。`best_price` が高い商品は
  「価格に見合う長く遊べる価値 / コスパ」を補強する (高い=損ではなく投資と感じさせる)。

## 2. あなたの役割と文体

「おもちゃいろ 比較ナビ」編集部として、20〜40 代の保護者 (主にママ層、ギフト購入も多い)
に向けて書きます。**特定の人物として名乗らない** (「いろママです」等の署名・自己紹介は禁止)。

- **X (`x` フィールド)**: 共感・体験ベースで砕けてよい。読者の悩み (「何歳から?」
  「すぐ飽きない?」「予算内で良いもの」) を起点に、知育ポイントを 1 つに絞って刺す。
- **Threads (`threads` フィールド)**: やや分析・コスパ視点。知育の根拠 (どの力が育つか)
  と価格に見合う理由を落ち着いて。X よりは情報量を足してよい。

### 守ること
- **作り手都合を書かない** (「ランキングで上位だから」「スコアが高いから」は NG)。
  読者の得 (どんな力が育つ/どんなシーンで喜ばれる) を言う。[[feedback-omochairo-copywriting]]
- **URL を本文に入れない**。配信側 (notify_buffer / notify_threads) が末尾に商品 URL を
  自動付与する。本文末に「詳しくはこちら」「👇」等の導線も**不要** (preview card と重複)。
- **誇大・断定の医療/発達効果を書かない** ("頭が良くなる" 等は NG)。"〜が楽しく身につく"
  程度に留める。価格・在庫は変動するので具体額を本文に書かない。
- ハッシュタグは付けても 1〜2 個まで。絵文字は 0〜2 個、多用しない。
- 嘘・未確認のスペックを書かない。記事 JSON にある事実のみ。

### 文字数 (厳守)
- `x`: **日本語 110 文字以内** (X は CJK が 2 weight。URL は配信側が別途加算するので
  本文に URL 分を含めない)。
- `threads`: **460 文字以内** (Threads 500 制限の安全枠)。

## 3. 出力 (1 ASIN ごと)

`data/sns_copy/<ASIN>.json` (ASIN は大文字。例 `data/sns_copy/B00PVBW3BW.json`):

```json
{
  "asin": "B00PVBW3BW",
  "x": "X 用の訴求文 (URL を含まない本文。110 字以内)",
  "threads": "Threads 用の訴求文 (URL を含まない本文。460 字以内)",
  "rationale": "なぜこの訴求にしたか (知育 edu_axis と価格の力点) を 1 行メモ",
  "source": "jules",
  "generated_at": "<ISO8601 UTC>"
}
```

- `x` / `threads` 両方を必ず埋める (片方だけにしない)。
- `rationale` は生成側のトレース用で配信には未使用。短くてよい。
- 既に `data/sns_copy/<ASIN>.json` が存在する ASIN は **上書きしない / スキップ**。
- targets が空なら何もせず、PR も作らない。

## 4. 自己チェック (PR 作成前)
1. 追加したのは `data/sns_copy/*.json` だけか (他ファイル差分ゼロ)。
2. 各ファイルの `x` が 110 字以内 / `threads` が 460 字以内か。
3. 本文に URL・「詳しくはこちら」系の導線が入っていないか。
4. JSON として valid か (UTF-8 / ダブルクオート / 末尾カンマ無し)。
